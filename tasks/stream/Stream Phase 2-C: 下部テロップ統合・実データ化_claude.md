# Claude用実装指示書

## `/live/stream` Stream Phase 2-C: 下部テロップ統合・実データ化

## 目的

`/live/stream` の下部速報テロップを、これまで実データ接続した4カテゴリの情報から動的生成する。

対象カテゴリ:

```text
地震
キキクル・豪雨
潮位・水位
鉄道
```

Phase 2-B.1〜2-B.4 で、各小窓は実データ接続済み。
今回の Phase 2-C では、それらの `scene` / ViewModel から配信用テロップ文言を生成する。

---

## 基本方針

テロップは、`/live/stream` の画面下部に常時表示される横流し情報とする。

目的:

```text
画面全体を見ていなくても、現在の注目情報が分かる
配信視聴者が途中から見ても状況を把握できる
地震・豪雨・潮位・鉄道を横断して1本の速報バーにまとめる
```

今回やること:

```text
各カテゴリの stream ViewModel から ticker items を生成する
重要度順に並べる
カテゴリラベルを付ける
テロップ本文を動的生成する
demo=1 / state=calm / 通常表示に対応する
取得失敗時と対象なしを区別する
既存E2Eを壊さない
```

今回やらないこと:

```text
音声読み上げ
YouTube API連携
複数行テロップ
管理画面
テロップ編集UI
外部配信用JSON API
履歴保存
DB追加
```

---

## 1. ticker用 ViewModel を作る

既存の `buildScene()` または scene生成処理の中で、下部テロップ用の配列を生成する。

例:

```js
scene.ticker = {
  items: [
    {
      id: "eq-202606301921",
      category: "earthquake",
      label: "地震",
      priority: 100,
      text: "19:21 岩手県沖 M6.1 最大震度5弱",
      severity: "high"
    },
    {
      id: "rain-shizuoka",
      category: "rain",
      label: "大雨",
      priority: 90,
      text: "静岡県中部 土砂災害キキクル「危険」",
      severity: "high"
    }
  ],
  text: "【地震】19:21 岩手県沖 M6.1 最大震度5弱 ／ 【大雨】静岡県中部 土砂災害キキクル「危険」"
};
```

テロップ描画側は `scene.ticker.text` または `scene.ticker.items` を受け取って表示する。

---

## 2. カテゴリ別テロップ生成ルール

### 地震

地震情報がある場合、最重要地震を1件表示する。

表示例:

```text
【地震】19:21 岩手県沖 M6.1 最大震度5弱
```

津波情報がある場合:

```text
【地震】19:21 岩手県沖 M6.1 最大震度5弱 - 津波の心配なし
```

または:

```text
【地震】19:21 岩手県沖 M6.1 最大震度5弱 - 津波情報あり
```

表示項目:

```text
発生時刻
震源名
M
最大震度
津波情報があれば短く
```

データ欠損時は `undefined`, `null`, `NaN` を出さない。

---

### キキクル・豪雨

対象がある場合、最重要対象を1件表示する。

表示例:

```text
【大雨】静岡県中部 土砂災害キキクル「危険」
```

または:

```text
【大雨】山梨県南部 キキクル「警戒」
```

表示項目:

```text
地域名
カテゴリ
危険度ラベル
```

通常雨は出さない。
対象なしの場合は、通常テロップには出さない。

---

### 潮位・水位

潮位は、警戒対象がある場合は優先して表示する。
警戒対象がない場合でも、代表地点の現在潮位・次の満潮情報を1件だけ表示してよい。

表示例:

```text
【潮位】東京 現在155cm / 満潮 05:38 184cm
```

または警戒時:

```text
【潮位】東京 現在210cm / 高潮に注意
```

Phase 2-C では高潮判定が未実装なら、平常データとして以下程度でよい。

```text
【潮位】東京 現在155cm / 満潮 05:38 184cm
```

表示項目:

```text
地点名
現在潮位
次の満潮または満潮情報
```

---

### 鉄道

ODPT由来の影響路線がある場合のみ表示する。

表示例:

```text
【鉄道】東京メトロ銀座線 遅延
```

区間や理由がある場合:

```text
【鉄道】中央線快速 三鷹〜東京で運転見合わせ
```

表示項目:

```text
路線名
状態
区間または理由
```

影響路線なしの場合は通常テロップには出さない。

ODPT対応範囲に限るため、全国鉄道全体の断定表現は避ける。

---

## 3. 優先順位

テロップ項目は重要度順に並べる。

基本優先順位:

```text
1. 地震 最大震度5弱以上、または津波情報あり
2. キキクル 災害切迫 / 危険
3. 鉄道 運転見合わせ / 運休
4. 潮位 警戒対象あり
5. 地震 その他の表示対象
6. キキクル 警戒 / 注意
7. 鉄道 遅延 / 運転変更
8. 潮位 代表地点の潮位
```

Phase 2-Cでは複雑にしすぎず、まず以下でもよい。

```text
地震 → 大雨 → 鉄道 → 潮位
```

ただし、将来的に priority 数値で並べ替えできる構造にしておく。

---

## 4. 件数が多い場合

テロップは長くなりすぎないよう、各カテゴリ最大1〜2件に制限する。

推奨:

```text
地震: 最大1件
大雨: 最大1件
鉄道: 最大1件
潮位: 最大1件
```

将来的には重要イベントが多い場合だけ、

```text
【大雨】静岡県中部ほか5件でキキクル危険
```

のようにまとめる。

Phase 2-Cでは、まず各カテゴリ1件でよい。

---

## 5. 対象なし時のテロップ

全カテゴリで表示対象がない場合:

```text
【監視中】現在、表示対象となる警戒情報はありません
```

または:

```text
【監視中】全国の地震・豪雨・潮位・交通影響を監視中
```

ただし、潮位の代表地点を常時出す場合は、完全な空にはなりにくい。

---

## 6. 取得失敗時の扱い

取得失敗カテゴリがある場合は、テロップに短く含めてもよい。

例:

```text
【鉄道】運行情報を取得できません
```

ただし、全部の取得失敗を長々流すと配信画面が重くなるため、優先度は低くする。

重要:

```text
取得失敗を「なし」と断定しない
```

禁止例:

```text
【鉄道】影響なし
```

取得失敗時にこれは出さない。

---

## 7. demo=1 の扱い

`demo=1` では、地震・豪雨・鉄道・潮位のデモ項目が必ずテロップに出るようにする。

URL例:

```text
/live/stream?state=alert&chrome=off&demo=1&demoNow=2026-06-30T19:42:00%2B09:00
```

期待テロップ例:

```text
【地震】19:21 岩手県沖 M6.1 最大震度5弱 ／ 【大雨】静岡県中部 土砂災害キキクル「危険」 ／ 【鉄道】中央線快速 三鷹〜東京で運転見合わせ ／ 【潮位】東京 現在155cm / 満潮 05:38 184cm
```

E2Eで安定して検証できるようにする。

---

## 8. state=calm の扱い

`state=calm` では、強制的に平穏テロップにする。

例:

```text
【監視中】現在、表示対象となる警戒情報はありません
```

または:

```text
【監視中】全国の地震・豪雨・潮位・交通影響を監視中
```

実データがあっても `state=calm` を優先する。

---

## 9. テロップ表示形式

既存デザインを維持する。

構成:

```text
左端: 速報タグ
右側: 横スクロール本文
```

例:

```text
速報 | 【地震】19:21 岩手県沖 M6.1 最大震度5弱 ／ 【大雨】静岡県中部 土砂災害キキクル「危険」
```

ラベル:

```text
地震
大雨
潮位
鉄道
監視中
```

区切り文字:

```text
／
```

## 10. アニメーション

既存の marquee 表現を維持する。

ただし、以下を守る。

```text
ticker本文が更新されたときだけmarqueeをリセットする
時計更新だけでmarqueeをリセットしない
毎秒DOM全体を作り直さない
```

demoNow指定時はテロップ内容が固定され、スクリーンショットが安定すること。

## 11. data-testid

既存 testid を維持する。

必須:

```text
live-stream-ticker
live-stream-ticker-body
```

追加推奨:

```text
live-stream-ticker-item
live-stream-ticker-label-earthquake
live-stream-ticker-label-rain
live-stream-ticker-label-rail
live-stream-ticker-label-tide
live-stream-ticker-label-monitoring
```

ただし、テロップ本文を1本の文字列として描画している場合は、`live-stream-ticker-body` のtextContent検証だけでもよい。

## 12. テロップ生成関数

専用関数を用意する。

例:

```js
function buildTickerItems(scene, options) {
  return [];
}

function buildTickerText(items) {
  return items.map(item => `【${item.label}】${item.text}`).join(" ／ ");
}
```

または既存構成に合わせる。

責務:

```text
sceneからticker itemを生成する
優先順位で並べる
件数制限する
空の場合は監視中文言を返す
```

---

## 13. 表示欠損対策

以下を画面に出さない。

```text
undefined
null
NaN
Invalid Date
[object Object]
```

欠損時の扱い:

```text
Mなし → M不明、またはM表示を省略
最大震度なし → 最大震度不明、または省略
地域名なし → 地域不明
路線名なし → 路線名不明
潮位なし → --cm
```

ただし、テロップは短くしたいため、欠損が多い項目は出さない方がよい。
