  # Claude用実装指示書

## `/live/stream` Stream Phase 2-B.2: キキクル・豪雨情報 実データ接続 MVP

## 目的

`/live/stream` の **キキクル・豪雨情報** を、既存 `/live` のデータ資源へ接続する。

Phase 2-B.1 では地震情報の実データ接続が完了した。
今回の Phase 2-B.2 では、次に `/live/stream` 左下の「キキクル・豪雨情報」小窓と、中央地図上の青系パルスを実データ化する。

今回の目的は以下。

```text
既存 /live のキキクル・豪雨系データ
  ↓
stream用 rain/kikikuru adapter
  ↓
buildScene()
  ↓
キキクル・豪雨小窓
中央地図の青系パルス
ヘッダー豪雨件数
必要に応じてテロップ先頭項目
```

---

## 重要方針

`/live/stream` は配信用ビューであり、通常 `/live` の全機能をそのまま再現しない。

今回のMVPでは、以下を優先する。

```text
注目対象の抽出
対象地域名の表示
危険度/警戒度の表示
中央地図上の青系パルス
複数対象の8秒巡回
データなし/取得失敗の区別
```

今回やらないこと。

```text
キキクルタイルの完全再現
洪水/浸水/土砂のレイヤー分割
雨雲タイルの精密表示
ランキングUIの完全移植
市区町村境界の完全表示
Leaflet / MapLibre への地図差し替え
backend APIの大規模追加
DB追加
```

---

## 1. 既存 `/live` のキキクル・豪雨データ取得口を調査する

まず既存 `/live` がどのAPIや状態を使っているか確認する。

調査対象候補:

```text
frontend/js/live/
live-rain-layer.js
live-kikikuru-layer.js
live-alert-panel.js
live-main.js
live-api-client 相当
backend /api/live/* 系
data_runtime/backend/live/* 系
```

確認すること:

```text
取得URL
レスポンス形式
強雨ランキング相当のデータ有無
キキクル危険度データ有無
対象地点/地域名
緯度経度または代表座標
危険度レベル
雨量/雨雲強度
更新時刻
データ取得失敗時の表現
```

既存 `/live` がすでに正規化済みの注目地域やランキングを持っている場合、それを優先する。
新規にJMAや気象庁タイルへ直接アクセスしない。

## 3. 対象抽出ルール

キキクル・豪雨は複数地点で同時発生するため、表示対象を絞る。

### 対象候補

以下のいずれかを対象にする。

```text
キキクル危険度あり地域
強雨ランキング上位地域
警報・注意報ではなく、実際に危険度または強雨が検出された地域
```

### 優先順位

既存 `/live` の方針に合わせ、基本は以下。

```text
1. 危険度が高い地域
2. 雨雲/雨量の強度が高い地域
3. 更新時刻が新しい地域
```

危険度例:

```text
災害切迫
危険
警戒
注意
```

通常雨は対象外。
配信画面では「普通の雨」を出さない。

---

## 4. 表示件数

左下小窓の左パネルには、最大5件程度を表示する。

```text
地域名
カテゴリ
レベルバッジ
更新時刻
```

例:

```text
静岡県 中部       危険
山梨県 南部       警戒
愛知県 東部       警戒
長野県 南部       注意
岐阜県 美濃       注意
```

件数が多い場合でも、配信画面では詰め込みすぎない。
最大5〜8件程度に制限する。

---

## 5. activeTarget 選択ルール

複数対象がある場合、8秒巡回で表示する。

最初に表示する対象は以下の優先順位。

```text
1. 危険度が最も高い
2. 雨雲/雨量強度が最も高い
3. 更新時刻が新しい
```

既存の `tick` / 8秒巡回の仕組みに乗せる。

地震小窓と同様に、毎秒DOM全体を再描画しない。
対象切替時のみ小窓地図/パルス/ポップアップを更新する。

## 6. キキクル・豪雨小窓の表示

### 左パネル

表示内容:

```text

カテゴリ
レベルバッジ
```

### 右地図

表示内容:

```text

青系パルス
雨域表現
ポップアップ
```

Phase 2-B.2 では、雨域は簡略表現でよい。

```text
ぼかし円
半透明の青い領域
簡略SVG
```

実タイルの完全再現は対象外。

---

## 7. 中央地図パルス

キキクル・豪雨の実データがある場合、中央地図上に青〜水色系パルスを表示する。

```text
lat/lon
  ↓
簡易日本地図SVG上の x/y
  ↓
豪雨パルス表示
```

地震と同様、簡略SVG上の概算位置でよい。
厳密な地図座標一致は不要。

パルス色:

```text
#2f7bff
#34d6ff
```

---

## 8. データなし時の挙動

実データ取得に成功し、表示対象が0件の場合:

```text
キキクル・豪雨小窓:
  現在、表示対象なし
  全国を監視中

中央地図:
  豪雨パルスなし

ヘッダー:
  豪雨 0
```

重要:

```text
データ取得成功 + 対象0 = 正常
データ取得失敗 = unavailable / error
```

この2つを混同しない。

---

## 9. 取得失敗時の挙動

API取得失敗・パース失敗・ネットワークエラー時は、画面全体を壊さない。

表示例:

```text
キキクル・豪雨情報
取得できません
```

または

```text
キキクル・豪雨情報
一時的に取得不可
```

禁止:

```text
キキクル・豪雨情報なし
```

取得失敗時に「なし」と断定しない。

console error は出さず、必要なら console.warn 程度にする。

## 10. state / demo パラメータとの関係

Phase 2-A / 2-B.1 の挙動を維持する。

### `state=calm`

強制平穏表示。
実データがあっても calm 表示を優先する。

### `state=alert&demo=1`

E2E安定用の警戒デモ表示。
キキクル・豪雨のダミーデータを必ず表示する。

### 通常表示

実データ取得を試みる。

```text
取得成功・対象あり → 実データ表示
取得成功・対象なし → 表示対象なし
取得失敗 → 取得不可表示
```

### `demoNow`

用途:

```text
時計固定
更新時刻表示の安定化
巡回・12時間相当判定がある場合の基準時刻
```

## 11. E2E安定化用 mock / demo

`demo=1` を地震だけでなく、キキクル・豪雨にも適用する。

例:

```text
/live/stream?state=alert&chrome=off&demo=1&demoNow=2026-06-30T19:42:00%2B09:00
```

このURLでは以下が保証されること。

```text
地震デモあり
キキクル・豪雨デモあり
中央地図に地震パルスあり
中央地図に豪雨パルスあり
ヘッダー豪雨件数が1以上
```

---

## 12. ヘッダーステータス反映

ヘッダー右側の豪雨件数を実データ由来にする。

```text
豪雨 0
豪雨 1
豪雨 5
```

対象は表示対象件数。

取得失敗時は以下のいずれか。

```text
豪雨 -
豪雨 取得不可
```

## 13. テロップは最小対応

今回、テロップ全面動的化は対象外。

ただし、キキクル・豪雨の実データがある場合、既存テロップの大雨項目だけ差し替えてもよい。

例:

```text
【大雨】静岡県中部に土砂災害キキクル「危険」
```

やりすぎないこと。
テロップ全体のイベント統合は Phase 2-C 以降。
