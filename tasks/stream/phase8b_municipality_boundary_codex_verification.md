# CODEX用検証指示書
## Phase 8-B: 小画面 市区町村境界線・自治体名表示改善 検証

## 検証目的

Claude実装後、`/live/stream` の地図系小画面に対して、以下を検証する。

- 市区町村境界線が適切に追加されているか
- 条件付きの市区町村名表示が機能しているか
- 情報過多になっていないか
- 既存の小画面機能や配信画面全体を壊していないか
- パフォーマンスへの悪影響が大きくないか

## 対象

主対象:

```text
/live/stream
```

対象小画面:

- 地震情報小画面
- キキクル小画面
- 豪雨/強雨系小画面  
  実際の実装名・DOM名に合わせて確認すること。

## 検証成果物

以下の検証レポートを作成する。

```text
tasks/live/live_phase8b_municipality_boundary_and_labels_codex_verification.md
```

判定:

- PASS
- PASS with notes
- FAIL

## 1. 実装差分確認

以下を確認する。

```bash
git diff --stat
git diff
```

確認観点:

- 市区町村境界線描画用のレイヤー/処理が追加されているか
- 自治体名ラベル処理が追加されているか
- 地震/キキクル/豪雨小画面それぞれに適用されているか
- 小画面共通処理として実装されているか、個別実装か
- 境界データ取得方法が過剰に重くないか
- 既存のレイヤー構成を壊していないか

## 2. 構文確認

対象JSの構文確認を行う。

例:

```bash
find frontend/js -name '*.js' -print0 | xargs -0 -n1 node --check
```

必要に応じて対象ファイルを絞ってよい。  
CSSを追加した場合は該当ファイルも確認する。

## 3. データ取得/境界データ確認

### 3.1 境界データの存在確認

- 市区町村境界データのソースを確認する。
- GeoJSON / TopoJSON / vector tiles 等の方式を確認する。

確認観点:

- データが軽量化・簡略化されているか
- 全国全件を毎回フルロードしていないか
- bbox ベースで処理されているか

### 3.2 エラー耐性

- 境界データ取得失敗時に主画面が壊れないか。
- console error を大量に出さないか。

## 4. UI確認: 地震小画面

### 確認項目

- 市区町村境界線が表示される。
- 線が薄く、震度情報より目立たない。
- 条件付きで市区町村名が表示される。
- 自治体名が震度マーカーや主要情報を隠していない。
- ラベルが過密になっていない。
- 震度分布の理解がしやすくなっている。

### 特に確認したいこと

- 震度のある自治体だけが優先的にラベル表示されているか。
- すべての自治体名が無差別に出ていないか。
- 小画面として成立しているか。

## 5. UI確認: キキクル小画面

### 確認項目

- 市区町村境界線が表示される。
- 線が薄く、危険度面を邪魔していない。
- 条件付きで自治体名が表示される。
- 危険自治体や上位自治体が優先表示されているか。
- ラベルが多すぎないか。
- 面情報の視認性が維持されているか。

### 特に確認したいこと

- 赤・紫系危険域の把握を邪魔していないか。
- 「危険自治体だけ分かる」方向になっているか。

## 6. UI確認: 豪雨/強雨小画面

### 確認項目

- 市区町村境界線が表示される。
- 線が雨雲表示を邪魔していない。
- 条件付きで自治体名が表示される。
- 強雨/豪雨の理解に役立つか。
- ラベル過密になっていないか。

### 特に確認したいこと

- ランキング対象自治体や高強度自治体の表示が自然か。
- 雨雲面の見やすさを壊していないか。

## 7. ラベル表示ルール確認

確認観点:

- 全自治体名を常時表示していないこと。
- 小画面ごとに条件付き表示になっていること。
- 件数制限があること。
- ラベル衝突回避や間引きがあること。
- 画面端や重なりの表示が破綻していないこと。

必要ならコード上で以下を確認する。

- 最大件数制御
- 優先度付け
- bbox フィルタ
- center proximity などの条件

## 8. スタイル確認

確認観点:

- 境界線が細く薄い。
- 自治体名が読める。
- 白文字 + 黒縁取り、または暗背景ラベルなどで視認性がある。
- YouTube縮小表示でも潰れにくい。
- 色が強すぎず、主情報と競合しない。

## 9. パフォーマンス確認

今回かなり重要。

### 確認項目

- 小画面更新時に極端な重さがない。
- 既存 `/live/stream` より大幅にCPU負荷が悪化していない。
- 地図更新時のチラつきや大きな遅延がない。
- ラベル追加によってブラウザエラーやメモリ膨張が起きていない。

### 可能なら確認するもの

- ブラウザ console error
- page error
- レイヤー増殖の有無
- DOM ノードや Leaflet layer の異常増加
- stream画面の体感遅延

必要なら簡易的に以下で前後比較してよい。

```bash
docker stats --no-stream
```

## 10. E2Eテスト確認

可能であれば専用E2Eを追加・実行する。

推奨ファイル名例:

```text
e2e/live-stream-mini-map-municipality-boundary.spec.js
```

テスト観点:

1. `/live/stream` を開く。
2. 地震小画面が表示される。
3. 境界線レイヤーが存在する。
4. 条件付きラベルが存在する。
5. キキクル小画面でも境界線が表示される。
6. 豪雨小画面でも境界線が表示される。
7. ラベル件数が過剰でない。
8. console error / page error がない。

注意:

- 視認性の最終評価は自動テストだけでなく目視も行うこと。

## 11. スクリーンショット確認

可能なら代表スクリーンショットを取得する。

候補例:

```text
test-results/live-stream-earthquake-mini-map-boundary.png
test-results/live-stream-kikikuru-mini-map-boundary.png
test-results/live-stream-rain-mini-map-boundary.png
```

確認観点:

- 境界線が見える。
- 文字が過密でない。
- 主情報が読みやすい。
- 小画面として成立している。

## 12. 回帰確認

既存の `/live/stream` 機能に影響がないことを確認する。

最低限:

- `/live/stream` が 200 OK
- 地震表示が壊れていない
- キキクル表示が壊れていない
- 豪雨/雨雲表示が壊れていない
- 全国気象が壊れていない
- 鉄道情報が壊れていない
- 潮位・水位が壊れていない
- 下部 ticker が壊れていない
- console error / page error がない

既存E2Eがあれば合わせて実行する。

## 13. 判定基準

### PASS

- 対象小画面に市区町村境界線が追加されている。
- 条件付きで自治体名が表示される。
- 情報過多になっていない。
- 視認性が向上している。
- 既存機能を壊していない。
- パフォーマンス劣化が許容範囲。

### PASS with notes

- 主要機能は満たす。
- 一部小画面でラベル密度に改善余地あり。
- 特定ケースでラベル優先度に改善余地あり。
- 目視スクリーンショット確認が限定的。
- 実データ条件が限定的。

### FAIL

- 境界線が出ない。
- ラベルが過密で画面が崩れる。
- 主情報を邪魔している。
- `/live/stream` の小画面機能を壊している。
- パフォーマンス悪化が大きい。
- console error / page error が継続発生する。
