# Claude用実装指示書
## Phase 8-B: 小画面 市区町村境界線・自治体名表示改善

## 目的

`/live/stream` の小画面のうち、以下の地図系サブパネルについて、**市区町村境界線** と **条件付きの市区町村名表示** を追加し、地理的な把握しやすさを向上させる。

対象:

- 地震情報小画面
- キキクル小画面
- 豪雨/強雨小画面  
  実装上の名称が異なる場合は、降雨・危険度系の小画面を対象とする。

目的は、視聴者が以下を小画面上で直感的に把握しやすくすること。

- どの自治体で揺れたのか
- どの自治体に危険度がかかっているのか
- 危険域が行政区画に対してどう広がっているのか

## 基本方針

### 1. 境界線は追加する

- 市区町村境界線は全体に表示してよい。
- ただし、かなり薄く、主張しすぎない。
- 面情報（キキクル・豪雨・震度）を邪魔しないこと。

### 2. 市区町村名は条件付き表示にする

- 全自治体名の常時表示は行わない。
- 小画面での情報過多を避ける。
- 地震小画面とキキクル/豪雨小画面で表示条件を変える。

### 3. パフォーマンスを重視する

- 境界データは可能な限り簡略化する。
- 小画面の表示範囲（bbox）内だけ描画する。
- ラベル数を制限する。
- 既存の `/live/stream` パフォーマンスを悪化させない。

## 対象画面

主対象:

```text
/live/stream
```

対象パネル:

- 地震情報の地図小画面
- キキクルの地図小画面
- 豪雨/強雨/雨雲由来の地図小画面  
  実際のUI名・DOM名に合わせること。

`/live` 本体側に同種の小画面が存在し、共通化しやすい場合は将来流用を見据えて実装してよい。  
ただし、今回の主対象は `/live/stream` とする。

## 実装スコープ

### 今回やること

- 市区町村境界線を小画面に表示する。
- 条件付きで市区町村名を表示する。
- 小画面ごとに表示ルールを分ける。
- 過密表示を防ぐ。
- パフォーマンスへの影響を抑える。

### 今回やらないこと

- 全自治体名の常時表示
- 都道府県境と市区町村境を同等強度で表示
- 地図全面ラベル化
- ラベル検索UI
- 境界クリックでポップアップ
- 境界線の過度な装飾
- `/live` 本体側の全面対応

## データ方針

### 境界線データ

- 市区町村境界 GeoJSON / TopoJSON / ベクトルタイル相当の既存資源があれば再利用する。
- 既存の Martin / タイル環境に乗せられるならそれを優先する。
- ただし、小画面用途では軽量性を優先する。
- 必要なら小画面専用に簡略化した境界データを使う。

### 推奨条件

- polygon fill は不要。線のみ表示する。
- geometry simplification を適用する。
- bbox 内のみ読み込み、またはベクトルタイルで必要範囲のみ描画する。
- 市区町村名の座標は centroid / representative point を利用してよい。

## 表示仕様

## A. 地震情報小画面

### 境界線

- 市区町村境界線を表示する。
- 線色は薄いグレーまたは半透明白。
- 線幅は細くする。
- 震度マーカーや背景色より目立たないこと。

### 市区町村名

表示対象は以下のいずれかとする。

優先案:

- 震度表示対象自治体のみ表示

代替案:

- 震度4以上の自治体だけ表示
- 上位3〜6件の自治体だけ表示
- 小画面に表示中の震度マーカーに対応する自治体だけ表示

### 表示方法

- 白文字 + 黒縁取り。
- または暗色半透明ラベル + 白文字。
- 文字サイズは小さめだが配信で読める範囲。
- ラベル衝突時は間引く。

### 注意

- 震度数字マーカーを隠さない。
- ラベル過多で画面が崩れないこと。

## B. キキクル小画面

### 境界線

- 市区町村境界線を表示する。
- 地震小画面よりさらに薄くてもよい。
- 面の危険度が主役なので、線は補助扱いにする。

### 市区町村名

表示対象は以下のいずれかとする。

優先案:

- 高危険度（赤・紫など）がかかっている自治体のみ表示

代替案:

- キキクル集計やランキング対象自治体のみ
- 危険度上位の自治体のみ
- 最大3〜5件程度まで

### 注意

- ラベルを増やしすぎると面情報の可読性が落ちる。
- 「危険な自治体だけ見える」方向にする。

## C. 豪雨/強雨小画面

### 境界線

- 市区町村境界線を表示する。
- 薄く、目立たせすぎない。

### 市区町村名

表示対象は以下のいずれかとする。

優先案:

- 強雨・豪雨ランキング対象自治体のみ表示

代替案:

- 一定閾値以上の降雨がかかる自治体のみ
- 最大5件程度まで
- 雨雲面そのものを邪魔しない範囲

### 注意

- 豪雨/強雨は面やランキングが主役。
- 自治体名は補助情報として扱う。

## ラベル表示ルール

### 共通ルール

- 全件表示しない。
- 最大件数を設ける。
- 表示優先度を定める。
- 重なった場合は間引く。
- 画面外や端すぎるラベルは抑制してよい。

### 推奨最大件数

- 地震小画面: 4〜8件程度
- キキクル小画面: 3〜5件程度
- 豪雨小画面: 3〜5件程度

### ラベル優先度の例

地震:

1. 震度が高い
2. 小画面中心に近い
3. 表示中の代表イベントに近い

キキクル:

1. 危険度が高い
2. 小画面中心に近い
3. 面積が大きい

豪雨:

1. 雨量/強雨スコアが高い
2. 小画面中心に近い
3. ランキング対象

## 見た目の仕様

### 市区町村境界線

推奨:

```text
色: rgba(255,255,255,0.18) 〜 rgba(200,200,200,0.30)
線幅: 0.5〜1.0px 程度
```

ダーク背景なら薄い白系、明るい背景なら薄いグレー系。

### 市区町村名

推奨:

```text
文字色: 白
縁取り: 黒
```

または:

```text
背景: rgba(0,0,0,0.35)
文字色: 白
角丸小ラベル
```

重要:

- YouTubeで潰れにくいこと。
- 背景とコントラストが取れること。

## パフォーマンス要件

今回の実装では、以下を重視すること。

### 必須

- 境界データの簡略化
- bbox 内だけ描画
- ラベル数制限
- 必要な小画面だけ処理
- 既存の地震・キキクル・豪雨の更新処理を過度に遅くしない

### 望ましい

- 境界データの一度読み込み後の再利用
- 小画面ごとの毎回全件走査を避ける
- ラベル候補の軽量化
- 可能なら feature index / spatial filter を利用

### 非推奨

- 小画面更新のたびに全国全自治体境界をフル走査
- すべての自治体名をDOM化
- 高頻度再描画で大量レイヤーを作り直すこと

## 実装方針

### 推奨

- 小画面用の boundary layer を追加する。
- 必要に応じて label layer を別で持つ。
- 既存の各小画面レイヤー構成に寄せる。
- 可能なら共通 utility 化する。

例:

```text
mini-map boundary layer
mini-map label layer
hazard/event layer
```

### 共通化候補

- `renderMunicipalityBoundaries(miniMap, bbox, options)`
- `renderMunicipalityLabels(miniMap, candidates, options)`
- `selectEarthquakeMunicipalityLabels(...)`
- `selectKikikuruMunicipalityLabels(...)`
- `selectHeavyRainMunicipalityLabels(...)`

## エラー時の扱い

- 境界データ取得失敗で `/live/stream` 全体を壊さない。
- ラベル生成に失敗しても主機能（地震・キキクル・豪雨表示）は継続する。
- console error を大量に出し続けない。
- 失敗時は境界線なし/ラベルなしにフォールバックしてよい。

## 受け入れ条件

### 共通

- `/live/stream` の対象小画面で市区町村境界線が表示される。
- 線は主張しすぎず、主情報を邪魔しない。
- パフォーマンス劣化が致命的でない。
- 既存の小画面表示を壊さない。

### 地震小画面

- 市区町村境界線が表示される。
- 条件付きで市区町村名が表示される。
- 震度情報の理解がしやすくなる。
- 震度マーカーを邪魔しない。

### キキクル小画面

- 市区町村境界線が表示される。
- 条件付きで危険自治体名が表示される。
- 面情報を邪魔しない。

### 豪雨小画面

- 市区町村境界線が表示される。
- 条件付きで自治体名が表示される。
- 雨雲/強雨表示を邪魔しない。
