# Claude 実装指示書

## 総合災害ビューア LIVE Phase 7-A.5 全国鉄道路線 PMTiles 化

## 目的

`/live` の鉄道路線表示を関東一部限定から全国対応へ拡張する。

現在、地震・雨雲・キキクルは全国対応済みだが、鉄道路線表示は関東中心であり、「全国災害ビューア LIVE」の思想と不整合がある。

本対応では、鉄道路線を単なる運行情報表示ではなく、災害時に地理感覚を補助するベースレイヤーとして扱う。

基本方針は以下。

```text
鉄道路線ベース表示 = PMTiles
運行情報・障害情報 = backend/API
```

全国鉄道路線をブラウザへ一括ロードしないこと。
PMTiles / vector tile により、画面表示範囲のタイルのみ取得・描画する。

---

# Phase 7-A.5-A

## 全国鉄道路線 PMTiles ベース表示

## 対象

まずは「路線のみ」を全国表示する。
駅・駅名・路線名ラベルはこのフェーズでは必須ではない。

## 実装要件

### 1. 全国鉄道路線データの作成

OSM 由来の全国鉄道路線データから PMTiles を生成する。

対象 railway tag の候補:

```text
railway=rail
railway=subway
railway=light_rail
railway=tram
railway=monorail
railway=narrow_gauge
```

除外候補:

```text
railway=abandoned
railway=disused
railway=construction
railway=razed
service=yard
service=siding
service=spur
usage=industrial
```

貨物線・側線・車庫線・引込線・工業線などが大量に出ると災害ビューアとして見づらくなるため、MVPでは抑制する。

### 2. PMTiles配置

生成した PMTiles は以下のような live 専用配置にする。

```text
frontend/data/live/railways/railways_japan.pmtiles
```

または既存構成に合わせた静的配信パスを採用する。

### 3. frontend 側読み込み

`/live` の鉄道レイヤーON時に PMTiles を読み込む。

既存の関東GeoJSON鉄道路線表示と競合しないこと。

鉄道レイヤーOFF時は PMTiles レイヤーを非表示にする。

### 4. 表示スタイル

初期スタイルは控えめにする。

```text
通常路線: 暗めのグレーまたは薄い白系
線幅: zoomに応じて変化
透明度: 災害情報を邪魔しない程度
```

雨雲・キキクル・地震マーカー・津波情報を邪魔しないこと。

### 5. zoom制御

低ズームでは線を出しすぎない。

目安:

```text
zoom <= 6:
  表示なし、または主要路線のみ

zoom 7-9:
  幹線中心

zoom >= 10:
  通常路線表示
```

データ属性で主要/非主要を分けられない場合は、まず zoom による線幅・透明度調整で対応してよい。

### 6. 既存運行情報との関係

このフェーズでは ODPT 運行情報との動的連携は行わない。

既存の障害路線カード・代表座標マーカー・ポップアップは維持する。

# Phase 7-A.5-B

## 駅レイヤー・駅名表示

## 目的

鉄道路線に加えて、駅を地理的な目印として表示する。

## 実装要件

### 1. 駅データ

OSM 由来の駅データを PMTiles に含める、または別 PMTiles として作成する。

対象候補:

```text
railway=station
railway=halt
station=subway
station=light_rail
```

### 2. 表示条件

駅はズーム段階で表示制御する。

目安:

```text
zoom < 9:
  駅は非表示

zoom 9-10:
  主要駅のみ

zoom >= 11:
  駅アイコン表示

zoom >= 12:
  駅名表示
```

主要駅判定が難しい場合、Phase 7-A.5-B MVPでは zoom >= 11 から駅アイコン、zoom >= 12 から駅名でよい。

### 3. ラベル衝突対策

駅名は地図を埋め尽くさないこと。

MapLibre等の symbol layer を使う場合は collision を有効にする。
Leaflet系で独自描画する場合は、既存の鉄道ラベル衝突制御と同等以上にする。

### 4. 既存UIとの整合

鉄道レイヤーON時のみ駅・駅名を表示する。
OFF時は路線・駅・駅名すべて消えること。

# Phase 7-A.5-C

## 運行情報・障害情報との連携

## 目的

PMTilesで表示する全国鉄道路線ベースに、既存のODPT運行情報・障害情報を重ねる。

## 実装要件

### 1. 責務分離

以下の分離を守る。

```text
PMTiles:
  静的な全国鉄道路線・駅

backend/API:
  ODPT等の運行情報・障害情報
```

PMTiles自体を頻繁に更新しない。
運行状態は API レイヤーで扱う。

### 2. 障害路線の強調

既存の状態分類を維持する。

```text
delay
partial
suspended
unknown
normal
```

表示例:

```text
遅延: 黄色系
一部運休: オレンジ系
運転見合わせ: 赤系
不明: グレー系
```

ただし公式カラー対応済みの既存方針がある場合はそれを尊重する。

### 3. マッチング

ODPTの路線名・事業者名と、PMTiles側の route/name/operator/ref などを照合する。

完全一致にこだわりすぎず、まずは既存実装と同等の表記ゆれ吸収を移植する。

### 4. 失敗時挙動

路線形状とのマッチングに失敗しても、既存の障害カード・代表座標マーカー・ポップアップは残す。

障害情報が消えたように見えないこと。

### 5. 災害情報優先

障害路線強調は有用だが、地震・津波・雨雲・キキクルより視覚的に強くなりすぎないこと。

# 共通品質要件

## 1. `/live` 専用

ナビ本体 `/` に影響を与えない。
既存OnHighGround2の通常避難ナビUIを壊さない。

## 2. スマホ負荷

全国鉄道路線を表示してもスマホで操作不能にならないこと。

以下を避ける。

```text
全国GeoJSON一括ロード
大量DOM marker
全駅名常時表示
move中の連続再描画
```

## 3. 既存機能回帰

以下を壊さない。

```text
地震履歴
市区町村震度マーカー
雨雲レイヤー
キキクル
津波警報UI
鉄道運行障害カード
道路レイヤー
```

## 4. 成果物

実装後、以下を簡潔に報告する。

```text
変更ファイル
PMTiles生成手順
PMTiles配置場所
表示ズーム条件
既存関東GeoJSONとの差し替え有無
既知の制約
```
