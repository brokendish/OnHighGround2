# 指示書: モバイル詳細パネルの3段階ボトムシート化

## 目的
`https://ohg.brokendish.org/live` のモバイル表示で、詳細パネル（`#live-alert-card`）が
展開時に地図を覆い隠す問題を解消する。現状の **2段階（peek / full）** スナップに
**中間段階 half** を追加し、**3段階（peek / half / full）** にする。
詳細を開いた直後のデフォルトを `half` にすることで、地図の上半分を常に見せ、
「いったん最小化してから地図を見る」操作を不要にする。

## 設計の前提（既存実装・変更しないこと）
- 詳細パネルは自前実装。Leaflet のコントロール/ポップアップには依存しない。
- `live-mobile.js` は **非破壊エンハンサ**。`#live-alert-card` 本体の中身は触らず、
  `MutationObserver` で再レンダリングを検知して `.sheet-scroll` でラップ＋ハンドル/ピーク行を付与する。
  **この非破壊方針を維持すること。** パネル本体の `innerHTML` 生成（`live-alert-panel.js`）には手を入れない。
- スワイプは `touchstart/touchmove/touchend` の素のJS。**ライブラリは追加しない。**
- スナップ位置は CSS 変数 + `transform: translateY()` + `transition` で制御。

## 着手前の必須ステップ（行ズレ防止）
過去調査時の参照行（live-mobile.js:164–215 / live.css:948）は**変更前のもの**。
着手前に以下を実施し、最新の実際の位置・変数名を確認してから編集すること。

1. `frontend/js/live/live-mobile.js` を開き、次を特定する:
   - スナップ位置の定義（現状の collapsed / expanded 相当の値・変数）
   - `touchstart` / `touchmove` / `touchend` ハンドラ本体
   - `touchend` の「どちらのスナップに確定するか」を決める判定ロジック
   - 初期表示時にどのスナップへ置いているか
2. `frontend/css/live/live.css` を開き、次を特定する:
   - `--sheet-collapsed`（およびあれば `--sheet-expanded` 等）の定義箇所と値
   - シート要素の `transform` / `transition` 指定箇所
3. 上記の実際の変数名・関数名・行番号を `report.md` などに控えてから着手する。

## 実装要件

### 1. スナップ位置を3段階に
CSS 変数に **half** を追加する。命名は既存に合わせる（例が `--sheet-collapsed` / `--sheet-expanded` なら `--sheet-half` を追加）。
- `half` の高さは **画面高の約46〜50%**（地図の上半分が残る値）。
  固定pxではなく可能なら `vh`/`dvh` か JS でのビューポート高基準で算出し、
  小画面・アドレスバー伸縮に耐えるようにする。
- 既存の collapsed（peek）/ expanded（full）の値は原則維持。

### 2. touchend の確定ロジックを3点対応に
現状の「2点のうち近い方」を、**3点（peek/half/full）対応**に変更する。要件:
- ドラッグ終了時の現在位置に最も近いスナップを基本とする。
- ただし **スワイプ速度（フリック）** を考慮する。`touchmove` 中に
  直近の移動量/経過時間から速度を持ち、`touchend` で閾値超なら
  「最寄り」ではなく**スワイプ方向の隣のスナップへ1段送る**
  （例: half 付近で上に速いフリック → full、下に速いフリック → peek）。
- 速度閾値・スナップ許容幅はコード上部に定数化し、調整しやすくする。

### 3. 初期スナップを half に
詳細が開かれた直後（`#live-alert-card` に内容が入った時）の初期位置を
**full ではなく half** にする。`MutationObserver` で内容描画を検知した初回に half へ。
※ ユーザーが手動で full/peek にした後は、その状態を不必要に half へ戻さないこと。

### 4. 地図オフセット連動（ピンがシートに隠れないように）
シート確定時、選択中地点がシートに被らないよう Leaflet 地図ビューを上方向にずらす。
- スナップ確定時（`touchend` 確定後、および初期 half 設定時）に、
  現在のシート高（CSS変数 or 実測 `getBoundingClientRect`）から
  「隠れない可視領域の中心」を求め、`map.panTo` / `map.setView` または
  `map.panBy` で選択地点をその中心付近へ寄せる。
- peek 時はオフセット 0（地図全面）に戻す。
- 対象は「現在選択中の地点」。選択地点の参照方法は既存実装に合わせる
  （選択時に保持している座標/マーカーがあればそれを使う）。
- アニメーションは Leaflet の `animate` オプションを使い、シートの transition と
  体感が揃うようにする。

### 5. ピーク行（任意・推奨）
peek（折りたたみ）状態のハンドル横1行に、開かずに把握できる**最重要サマリ**
（例: 最高警戒レベルの災害種別＋地点名）を出す。
- これは非破壊方針の範囲で、エンハンサ側がパネル内容から要約を読み取って
  ピーク行に表示する形にする（パネル本体の生成は変えない）。
- データ取得が複雑なら本項はスコープ外として後続PRに回してよい。

## 触ってよい / いけないファイル
- 変更可: `frontend/js/live/live-mobile.js`, `frontend/css/live/live.css`
- 原則変更不可: `live-alert-panel.js`（パネル本体生成）, Leaflet 関連の既存初期化、
  PC表示のCSS（モバイル用メディアクエリ外を壊さないこと）

## テスト観点（実機/エミュレータ）
- iOS Safari / Android Chrome の実機相当でスナップ3段階が動く。
- 詳細を開いた初期表示が half。地図上半分が見えている。
- half / full で選択ピンがシートに隠れない（地図が上に寄る）。peek で地図全面に戻る。
- フリック上下で1段送り、ゆっくりドラッグで最寄り確定。
- アドレスバー伸縮・画面回転・小型端末（iPhone SE 幅 375px 相当）で half がはみ出さない。
- パネル再レンダリング（雨雲時刻更新など）で MutationObserver が誤発火して
  勝手に half へ戻らない（初期化は初回のみ）。
- PC表示・既存の peek/full 挙動にデグレがない。
