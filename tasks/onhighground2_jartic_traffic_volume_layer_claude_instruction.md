# OnHighGround2 Phase 7-B.3
# JARTIC 道路交通量・色分けマーカーレイヤー 実装指示書（Claude用）

## 0. 指示

OnHighGround2 通常画面へ、`/live` 側ですでに実装・運用されている JARTIC 道路交通量の色分けマーカー表示を追加してください。

今回の目的は新しい交通量表現を別途設計することではありません。**LIVE側で実績のある取得・正規化・色分け・ポップアップ・凡例の仕様を確認し、OnHighGround2通常画面へ同一意味・同一色・同一判定で移植または共通利用すること**です。

独自実装を増やしてLIVE側と表示意味が分岐しないようにしてください。

---

## 1. 背景

現在の `/live` 画面では、JARTIC交通量観測点が道路網に沿って色分け表示されています。

この表示により、単なる観測点位置だけでなく、以下を直感的に把握できます。

- 道路ごとの交通量の多寡
- 周辺道路との相対的な交通集中
- 幹線道路・橋・都市部への交通集中
- 鉄道障害や災害発生時における道路交通への影響

OnHighGround2通常画面にも同じ交通量レイヤーを追加し、避難経路・現在地・災害情報と交通状況を同一画面で確認できるようにします。

この機能は渋滞情報そのものではなく、**避難・移動判断を補助する道路交通量レイヤー**として扱います。

---

## 2. 目的

OnHighGround2通常画面に「道路交通量」レイヤーを追加し、利用者が必要なときだけLIVE画面と同一仕様の交通量色分けマーカーを表示できるようにします。

必須要件は以下です。

- 右側レイヤー一覧に「道路交通量」トグルを追加
- 初期状態はOFF
- LIVE側と同じ交通量取得・集計・色分け判定を使用
- LIVE側と同じ色の意味を使用
- LIVE側と同等のポップアップ情報を表示
- 同一画面内に交通量凡例を表示
- 表示範囲・ズームに応じて負荷を抑制
- 既存の避難所・経路・現在地・災害レイヤーを妨げない
- PC・モバイル双方で利用可能

---

1. 既存の共通モジュールをそのまま利用
2. LIVE固有コードから純粋な共通処理だけを分離
3. 共通化が過大改修になる場合は、判定定数・データ形式・表示仕様だけを共有

今回の小規模機能追加のために、大規模なフロントエンド再編や全面リファクタリングは行わないでください。

## 4. UI要件

### 4.1 レイヤートグル

OnHighGround2通常画面の右側レイヤー一覧に、次の項目を追加してください。

```text
道路交通量
```

配置は、既存の道路・鉄道・交通関連レイヤーの近くを優先してください。

要件:

- チェックボックスまたは既存トグル形式に統一
- 初期状態はOFF
- PC・モバイルとも表示
- ラベル省略や別名への変更はしない
- 既存レイヤー設定保存がある場合は同じ仕組みに組み込む
- OFF時はマーカーと凡例を完全に非表示
- OFF時は不要な再取得を行わない

### 4.2 マーカー

LIVE側と同じ色分け・意味・判定ロジックを使用してください。

重要:

- OnHighGround2側独自の閾値を新設しない
- LIVE側と同じ観測点が異なる色にならない
- マーカーサイズ・枠線・透明度は地図上で視認可能にする
- 避難所・地震・津波・現在地・経路より過度に目立たせない
- 地図上に大量表示しても判読不能にならないよう既存LIVE実装を踏襲

### 4.3 色の意味

色・カテゴリ・文言はLIVE側の現行実装を正とします。

たとえばLIVE側が以下の分類なら、そのまま使用してください。

```text
交通量が多い
標準的
交通量が少ない
データ不明
```

ただし、実際の分類名・色・閾値は必ずコードを確認して合わせてください。

**交通量の絶対値または独自指数から、渋滞・混雑と断定してはいけません。**

禁止例:

```text
渋滞中
道路が混雑しています
通行困難
```

許容例:

```text
交通量：多い
交通量：標準
交通量：少ない
交通量データなし
```

### 4.4 凡例

レイヤーON時のみ、交通量の色分け凡例を表示してください。

要件:

- LIVE側と同じ色・文言・順序
- 地図UIを過度に圧迫しない
- 既存凡例パネルへ統合できる場合は統合
- モバイルで横幅を超えない
- 情報パネルや閉じる操作を妨げない
- レイヤーOFF時に消える

既存の折りたたみ可能な凡例UIがある場合は、その形式を優先してください。

## 5. データ取得要件

### 5.1 既存APIの再利用

可能な限りLIVE側が利用している既存バックエンドAPIを再利用してください。

同じJARTICデータを画面ごとに別の形式で再取得・再正規化するAPIは新設しないでください。

ただし、通常画面に必要なBBOX・ズーム・件数指定が既存APIで不足している場合は、既存仕様を壊さない後方互換の拡張を検討してください。

### 5.2 BBOX取得

全国全件を毎回ブラウザへ返し、フロント側だけで絞り込む実装は避けてください。

基本方針:

- 現在の地図表示範囲からBBOXを生成
- 必要な範囲だけバックエンドへ要求
- 地図移動完了後に再取得
- 短時間の連続操作はデバウンス
- 前回通信が不要になった場合はキャンセル可能にする
- 同一BBOX・同一条件の連続取得を避ける

LIVE側に同等制御がある場合はそのまま踏襲してください。

### 5.3 ズーム制御

低ズーム時に全国の観測点を大量描画しないでください。

LIVE側に既存の最小ズーム・間引き・取得上限制御がある場合は同じ仕様を使用します。

既存仕様がない場合のみ、通常画面向けに以下を検討してください。

- 一定未満のズームでは取得しない
- 「拡大すると道路交通量を表示します」等の非断定ガイドを表示
- 中ズームでは取得件数を制限
- 高ズームでは表示範囲内を通常表示

閾値は地図の実データ密度と描画負荷を確認して決定してください。根拠なく固定値を増やさないでください。

### 5.4 時刻・最新データ

LIVE側と同じ最新時刻選択・時間コード決定方式を利用してください。

過去にJARTIC API Gatewayで、CQLフィルターのフィールド名をダブルクォートしたことで400となった問題がありました。

CQLは既存の正常実装を変更せず、以下のような形式を維持してください。

```text
時間コード={time_code} AND BBOX(ジオメトリ,...)
```

次のようにフィールド名をダブルクォートしないでください。

```text
"時間コード"={time_code}
```

### 5.5 キャッシュ

同一時刻・近似BBOXへの重複アクセスを抑制してください。

既存バックエンドキャッシュがある場合は利用し、通常画面専用の別キャッシュを重ねて複雑化しないでください。

## 6. ポップアップ要件

観測点クリック時に、LIVE側と同等の情報を表示してください。

最低限:

- 観測点コード
- 方向（上り・下り等）
- 交通量
- 観測時刻
- 交通量カテゴリまたは状態
- 出典

データに存在する場合:

- 小型車
- 大型車
- 車種不明
- 合計
- 5分値または1時間値の別

表示例は以下ですが、実際のデータ形式とLIVE側UIへ合わせてください。

```text
道路交通量 観測点 #5110130
方向：下り
交通量（5分値）：170台
交通量（1時間値）：—
状態：交通量が多い
観測時刻：2026-07-25 10:45
出典：国土交通省 道路交通量API（JARTIC提供）
```

注意書きとして、交通量から渋滞・通行可否を断定できないことを示してください。

例:

```text
交通量APIの値から推定した表示であり、通行止め・規制を断定するものではありません。
```

LIVE側に既存文言がある場合は同じ文言を使用してください。

## 7. レイヤーライフサイクル

以下を正しく実装してください。

### ON時

1. レイヤーグループ作成または再利用
2. 現在BBOX・ズームを確認
3. 取得条件を満たす場合のみAPI呼び出し
4. 古いマーカーを安全に置換
5. 凡例表示
6. 地図移動・ズームイベントを有効化

### OFF時

1. 進行中通信をキャンセルまたは結果を無視
2. マーカーを地図から除去
3. レイヤーグループをクリア
4. 凡例を非表示
5. 専用イベントリスナーを解除または無効化
6. OFF中にバックグラウンド再取得しない

### 再ON時

- 現在の表示範囲で再取得
- 古いBBOXのデータを一瞬表示しない
- イベントリスナーを多重登録しない

## 8. 既存機能との関係

以下へ回帰を起こさないでください。

- 現在地表示
- 避難所マーカー
- 避難経路表示
- 安全地点表示
- 地震情報
- 津波情報
- 高潮・洪水・土砂等の災害レイヤー
- 雨量レーダー
- 鉄道レイヤー
- LIVE遷移ボタン
- 情報パネル
- モバイルボトムシート
- 警告UI
- 地図のズーム・パン

交通量マーカーは避難経路や現在地を隠しすぎないようにしてください。

必要であれば、交通量レイヤーのpaneまたはz-indexを既存レイヤー設計に合わせて設定します。ただし、モーダル・情報パネル・警告UIより前面に出してはいけません。

## 9. パフォーマンス要件

OnHighGround2は低スペックVPSで運用しているため、機能追加による負荷増大を抑えてください。

必須:

- 初期OFF
- OFF時は通信・描画しない
- BBOX取得
- 地図操作のデバウンス
- 同一条件の重複取得回避
- レイヤー切替時の多重リスナー防止
- マーカー全再生成の回数を抑制
- 不要なポーリングを新設しない
- LIVE側と通常画面側から同時アクセスされてもバックエンドが過度に重複取得しない

可能であれば確認:

- 取得件数
- API応答時間
- ブラウザ描画時間
- メモリ増加
- レイヤーON/OFF反復後のリスナー・マーカー残留

---

## 10. エラー・空データ時

API失敗や0件時に、誤った断定表示をしないでください。

### API失敗

例:

```text
道路交通量：取得できません
```

### 表示範囲内0件

例:

```text
この範囲に交通量観測点はありません
```

### 低ズームで非表示

例:

```text
地図を拡大すると道路交通量を表示します
```

次のような誤表示は禁止です。

```text
交通量なし
道路は空いています
渋滞なし
```

エラーはコンソールへ無制限に繰り返し出力しないでください。

## 15. 実装上の重要原則

最後に、以下を必ず守ってください。

- LIVE側と通常画面側で交通量の意味を分岐させない
- 同一ロジックを安易にコピーして二重管理しない
- 渋滞情報と断定しない
- 初期OFFを維持する
- 表示範囲外を大量取得しない
- 低スペックVPSへの負荷を増やしすぎない
- 既存UI・既存災害レイヤーを壊さない
- MVPを越えた履歴分析や経路連携へ広げない

今回のゴールは、**LIVEで実績のある交通量可視化を、OnHighGround2の避難・移動判断画面へ安全に横展開すること**です。
