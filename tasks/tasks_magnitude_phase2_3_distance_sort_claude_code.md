# Magnitude Phase2-3 実装指示書（Claude Code）
## 現在地から近い順ソート対応

## 目的

Magnitudeモードの地震リストに「現在地から近い順」ソートを追加する。

既存の「新しい順」表示に加えて、ユーザーの現在地から震源までの距離が近い地震を優先表示できるようにし、地震情報をより「自分ごと」として把握しやすくする。

---

## 背景

Phase2-2 までで、Magnitudeモードは以下に対応済み。

```text
・地震ピン表示
・地震リスト表示
・現在地からの距離表示
・避難所レイヤー一時非表示
・新着地震の差分ハイライト
```

次の段階として、地震リストの並び順を切り替えられるようにする。

---

## 実装スコープ

### やること

```text
・地震リストにソート切替UIを追加
・新しい順 / 近い順 を切替可能にする
・現在地が取得できる場合は距離順で並び替える
・現在地がない場合は近い順を無効化、または選択時に説明表示する
・リストクリック時のピン連動を維持する
・新着NEWバッジ、直近強調、距離表示を維持する
```

### やらないこと

```text
・自動ポーリング
・WebSocketリアルタイム受信
・震度フィルタ
・避難誘導連動
・距離による地図ピンの表示制御
```

## 基本仕様

### ソート種別

```text
newest:
  発生時刻の新しい順

nearest:
  現在地から震源までの距離が近い順
```

初期値:

```text
newest
```

## 現在地が取得できている場合

```text
・近い順ボタンを有効にする
・近い順選択時、距離が近い順にリストを並び替える
・距離表示は既存どおり表示する
```

---

## 現在地が取得できていない場合

以下のどちらかで実装する。

### 推奨

```text
・近い順ボタンを disabled にする
・説明文を表示する
```

表示例:

```text
現在地を取得すると、近い順で並び替えできます。
```

### 代替

```text
・近い順を押したら現在地未取得メッセージを表示
・並び順は新しい順のまま維持
```

## 距離計算

既に距離表示で使用している `distanceKm` 相当の関数を再利用すること。

要件:

```text
・lat/lng がない地震は距離順では末尾に送る
・現在地がない場合は距離計算しない
・距離値はリスト表示とソート判定で一貫させる
```

---

## ソート処理

### 新しい順

```js
items.sort((a, b) => new Date(b.occurred_at) - new Date(a.occurred_at));
```

### 近い順

疑似コード:

```js
function sortByDistance(items, currentLocation) {
  return [...items].sort((a, b) => {
    const da = getEarthquakeDistanceKm(a, currentLocation);
    const db = getEarthquakeDistanceKm(b, currentLocation);

    if (da == null && db == null) return compareByNewest(a, b);
    if (da == null) return 1;
    if (db == null) return -1;

    if (da !== db) return da - db;
    return compareByNewest(a, b);
  });
}
```

同距離、または距離不明同士の場合は新しい順にする。

## 状態管理

Magnitude側に現在のソート状態を持つ。

例:

```js
let magnitudeSortMode = 'newest';
```

状態はページリロードでリセットしてよい。  
同一セッション内で Magnitude ON/OFF しても、可能なら最後の選択を維持してよい。

---

## リストとピンの関係

重要:

```text
ソートはリスト表示順のみ変更する。
地図ピンの位置や表示有無は変更しない。
```

リストクリック時:

```text
・該当ピンへ移動
・ポップアップを開く
・リスト選択状態を付与
```

既存挙動を維持すること。

---

## NEWバッジとの関係

Phase2-2 の新着ハイライトを維持する。

```text
・近い順でもNEWバッジは表示される
・NEW地震が必ず先頭固定になる必要はない
・ただし視認性は維持する
```

優先順位:

```text
ソート順 > NEWの有無
```

つまり、近い順を選択した場合は、NEWであっても距離順に従う。


## エッジケース

### 1. 現在地なし

```text
・近い順が無効、または選択できても新しい順のまま
・JSエラーなし
```

### 2. lat/lngなし地震

```text
・新しい順では通常表示
・近い順では末尾
・距離表示は「未取得」または非表示
```

### 3. 同距離

```text
・新しい順で安定ソート
```

### 4. API再取得

```text
・現在のソートモードを維持
・NEWバッジも維持
```

## 実装順序

1. 既存の距離計算処理を確認する
2. magnitudeSortMode を追加する
3. リスト描画前に sortMagnitudeItems を通す
4. 新しい順ソートを実装する
5. 近い順ソートを実装する
6. ソート切替UIを追加する
7. 現在地なし時のdisabled/説明表示を実装する
8. API再取得後もソート状態を維持する
9. Phase2-2のNEW表示との両立を確認する
10. Magnitude ON/OFF連続操作で状態が壊れないことを確認する

---

## 完了条件

以下を満たすこと。

```text
・初期表示は新しい順
・新しい順/近い順を切り替えられる
・近い順では現在地から近い地震が上に来る
・現在地なし時にUIが破綻しない
・lat/lngなし地震は近い順で末尾になる
・リストクリックでピン連動する
・NEWバッジ、新着件数、ピン強調が壊れない
・避難所一時非表示が壊れない
・連続ON/OFFでDOM/イベント/ピンが増殖しない
```
