# Magnitude Phase2-2 検証指示書（CODEX）
## 新着地震の差分ハイライト対応

## 目的

Magnitudeモードで地震情報を再取得した際、新着地震だけが正しく強調表示されることを検証する。

また、初回表示で全件NEWにならないこと、連続更新やモード切替でDOM・ピン・イベントが増殖しないことを確認する。

---

## 検証対象

```text
Magnitude Phase2-2: 新着地震の差分ハイライト
```

対象外:

```text
・WebSocketリアルタイム受信
・自動ポーリング
・通知機能
・避難誘導連動
```

# 2. 初回表示確認

手順:

```text
1. ページをリロード
2. MagnitudeモードをON
3. 地震情報を表示
```

確認:

```text
・地震ピンが表示される
・地震リストが表示される
・初回表示では全件NEWにならない
・新着件数表示が出ない、または0件扱い
```

合格条件:

```text
初回表示で全地震がNEW扱いにならないこと
```

# 3. 新着差分確認

## 3.1 APIレスポンスをモックできる場合

Playwrightなどで `/api/earthquakes` をモックし、2回目のレスポンスに新規 event_id を追加する。

### 1回目レスポンス例

```json
{
  "items": [
    {
      "event_id": "eq-001",
      "occurred_at": "2026-04-29T10:00:00+09:00",
      "epicenter_name": "相模湾",
      "lat": 35.2,
      "lng": 139.3,
      "depth_km": 20,
      "magnitude": 4.2,
      "max_intensity": "3",
      "tsunami_info": "津波の心配なし",
      "source": "mock"
    }
  ]
}
```

### 2回目レスポンス例

```json
{
  "items": [
    {
      "event_id": "eq-002",
      "occurred_at": "2026-04-29T10:05:00+09:00",
      "epicenter_name": "東京湾",
      "lat": 35.5,
      "lng": 139.8,
      "depth_km": 30,
      "magnitude": 4.8,
      "max_intensity": "4",
      "tsunami_info": "津波の心配なし",
      "source": "mock"
    },
    {
      "event_id": "eq-001",
      "occurred_at": "2026-04-29T10:00:00+09:00",
      "epicenter_name": "相模湾",
      "lat": 35.2,
      "lng": 139.3,
      "depth_km": 20,
      "magnitude": 4.2,
      "max_intensity": "3",
      "tsunami_info": "津波の心配なし",
      "source": "mock"
    }
  ]
}
```

確認:

```text
・eq-002 のみNEW表示される
・eq-001 はNEW表示されない
・新着件数が1件と表示される
・eq-002 のピンだけ強調される
```

---

## 3.2 実APIのみの場合

実APIでは都合よく新着が来ない可能性があるため、以下のいずれかで検証する。

```text
・フロント側のテストで一時的にモックデータを注入
・Playwright route でAPIを差し替え
・開発用の手動テスト関数があれば利用
```

実APIだけで新着を待つ検証は行わなくてよい。

# 4. NEWバッジ表示確認

確認:

```text
・新着リスト項目にNEWバッジが出る
・既存リスト項目にはNEWバッジが出ない
・NEWバッジ表示でレイアウトが崩れない
・スマホ幅でも表示が破綻しない
```

---

# 5. 新着ピン強調確認

確認:

```text
・新着ピンだけ強調される
・既存ピンは通常表示
・既存の時間帯色分けは維持される
・一定時間後に強調が解除される、または仕様どおり保持される
```

---

# 6. 新着件数表示確認

確認:

```text
・新着がある場合のみ表示される
・件数が正しい
・次回更新で新着がなければ消える、または0件扱いになる
・表示が地震リストやボタン操作を邪魔しない
```

---

# 7. 連続更新確認

手順:

```text
1. MagnitudeモードON
2. 更新操作を5回以上連続実行
```

確認:

```text
・同じevent_idが何度もNEWにならない
・ピンが増殖しない
・リスト項目が重複しない
・イベントハンドラが多重登録されない
・console error がない
```

---

# 8. Magnitude ON/OFF 回帰確認

手順:

```text
1. Magnitude ON/OFF を10回連続で実行
2. 必要に応じて更新操作も混ぜる
```

確認:

```text
・MagnitudeパネルDOMが増殖しない
・地震ピンがOFF後に残らない
・NEWバッジがOFF後に残らない
・タイマー由来のJSエラーがない
・避難所一時非表示/復元が壊れていない
```

---

# 9. 非同期競合確認

可能であればAPIレスポンスを遅延させて確認する。

手順:

```text
1. 1回目のAPIレスポンスを遅延させる
2. その間に2回目の更新を実行
3. 2回目を先に返す
4. 1回目を後から返す
```

確認:

```text
・古いレスポンスで最新表示が上書きされない
・newEventIds が壊れない
・表示順が破綻しない
```

---

# 10. 地震API失敗時確認

手順:

```text
1. /api/earthquakes を一時的に失敗させる
2. 更新操作を実行
```

確認:

```text
・取得失敗メッセージが出る
・既存表示が不自然に消えない、または仕様通り安全にクリアされる
・knownEventIds が壊れない
・次回正常取得時に復帰できる
```

---

# 11. XSS回帰確認

モック可能な場合、以下のような文字列を epicenter_name に入れる。

```html
<img src=x onerror=alert(1)>
```

確認:

```text
・HTMLとして実行されない
・文字列として安全に表示される
・NEWバッジ追加によりXSS対策が崩れていない
```

---

# 12. Phase2-1 回帰確認

避難所一時非表示が壊れていないこと。

確認:

```text
・避難所ON状態でMagnitude ON → 避難所非表示
・Magnitude OFF → 避難所復元
・避難所OFF状態でMagnitude ON/OFF → OFF維持
・広域クラスタもMagnitude中は非表示
・非同期の避難所取得戻りでゾンビ復活しない
```

---

# 13. 既存機能回帰確認

通常モードで確認。

```text
・ハザードレイヤー表示
・避難所レイヤー表示
・避難所クラスタ表示
・現在地表示
・ナビ開始
・サイドパネル開閉
・右側ボタン群
```

---

# 14. 合格条件

以下をすべて満たすこと。

```text
・初回表示で全件NEWにならない
・再取得時に新規event_idのみNEWになる
・NEWバッジが正しく表示される
・新着ピンのみ強調される
・新着件数が正しく表示される
・同じevent_idが繰り返しNEWにならない
・連続更新でDOM/ピン/イベントが増殖しない
・Magnitude ON/OFFで状態が壊れない
・地震API失敗後も復帰できる
・XSS対策が維持されている
・Phase2-1の避難所一時非表示が壊れていない
```

---

# 15. NG条件

以下が1つでもあれば不合格。

```text
・初回表示で全件NEWになる
・既存地震が毎回NEWになる
・ピンが増殖する
・リストが重複する
・古いAPIレスポンスで新しい表示が上書きされる
・Magnitude OFF後にタイマー由来のエラーが出る
・避難所一時非表示が壊れる
・XSSが再発する
```
