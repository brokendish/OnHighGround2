# OnHighGround2 ルート危険区間アウトライン表示 実装指示書（Claude Code向け）

## 目的

OnHighGround2 のルート表示に、候補ルート色を維持したまま、危険区間だけを外枠色で強調する表示を追加する。

現状はルート全体の危険度スコアと説明文は表示できているが、ユーザーが「どの区間が危険なのか」「この先危険区間に入るのか」を直感的に把握しにくい。

本対応では、ルート線を以下の状態に分けて可視化する。

```text
通常区間   ：ベースルート色のみ
注意予告   ：ベースルート色 + 黄色アウトライン
危険区間   ：ベースルート色 + 赤色アウトライン
復帰注意   ：ベースルート色 + 黄色アウトライン
```

## 実装方針

ルート本体の色は候補ルート色を維持する。

- 候補1: 既存の候補1色
- 候補2: 既存の候補2色
- 候補3: 既存の候補3色

危険状態は、ルート本体の色を塗り替えるのではなく、太めのアウトラインとして重ね描画する。

これにより、以下を両立する。

- どの候補ルートか分かる
- どの区間が危険か分かる
- ハザードレイヤーや地図背景と混ざりにくい

## 対象範囲

主に以下を確認し、必要な箇所を修正する。

- `frontend/js/navigation.js`
- `frontend/js/map.js`
- `frontend/js/hazard-layers.js`
- `frontend/css/*.css`
- ルート描画・候補ルート切替・risk scoring に関係する既存ファイル

実際のファイル名は現行実装に合わせること。

## 表示仕様

### 1. 通常区間

```text
ベースルート色のみ
```

通常区間は既存のルート表示と同等にする。

### 2. 注意予告区間

```text
ベースルート色 + 黄色アウトライン
```

危険区間の手前を黄色アウトラインで表示する。

初期値は以下を推奨する。

```js
const ROUTE_RISK_PREVIEW_M = 30;
```

### 3. 危険区間

```text
ベースルート色 + 赤色アウトライン
```

実際にハザードと重なる区間を赤色アウトラインで表示する。

対象ハザードは、まず既存の route risk scoring に使っているものを使う。

- flood
- lowland_poor_drainage
- inland_flood / pseudo_inland_flood が既に risk scoring に入っている場合はそれも対象

新しいハザード判定系を大きく作り直さないこと。
既存の risk scoring / intersection 判定結果を再利用できる場合は、それを優先する。

### 4. 復帰注意区間

```text
ベースルート色 + 黄色アウトライン
```

危険区間を抜けた直後を黄色アウトラインで表示する。

初期値は以下を推奨する。

```js
const ROUTE_RISK_RECOVERY_M = 20;
```

## レイヤー構成

ルートは以下のように重ねる。

```text
下: 危険アウトライン layer
中: 注意アウトライン layer
上: 既存ルート本体 layer
```

または Leaflet の pane / zIndex を使って以下を満たすこと。

- アウトラインがルート本体の下に見える
- ルート本体の候補色が潰れない
- 現在地マーカーや目的地マーカーを隠さない
- 避難所アイコンやハザードレイヤーとの視認性を大きく損なわない

## 色・太さの推奨値

既存デザインに合わせて調整してよいが、初期値は以下を推奨する。

```js
const ROUTE_RISK_OUTLINE = {
  caution: {
    color: '#facc15',
    weightOffset: 8,
    opacity: 0.9,
  },
  danger: {
    color: '#ef4444',
    weightOffset: 10,
    opacity: 0.95,
  },
};
```

既存ルート weight が `8` の場合、アウトライン weight は以下のようにする。

```js
outlineWeight = baseWeight + weightOffset;
```

## セグメント分割仕様

ルート geometry を距離ベースでセグメント化する。

各セグメントは以下のような構造を想定する。

```js
{
  coords: [[lat, lng], [lat, lng]],
  startDistanceM: 120,
  endDistanceM: 145,
  riskState: 'normal' | 'caution' | 'danger',
  hazardTypes: ['flood', 'lowland_poor_drainage']
}
```

実装上、既存の座標形式が `[lng, lat]` の場合は、既存実装に合わせること。
Leaflet に渡す直前で形式を統一すること。

## riskState 判定

まず `danger` を確定する。

- ハザードと重なる区間を `danger` にする
- 複数ハザードが重なる場合も `danger`

次に `danger` の前後を `caution` にする。

- `danger` 開始点の `ROUTE_RISK_PREVIEW_M` 手前を `caution`
- `danger` 終了点の `ROUTE_RISK_RECOVERY_M` 後ろを `caution`
- ただし `danger` を `caution` で上書きしない

複数の危険区間が近接している場合は、黄色区間がつながってもよい。

## 描画仕様

危険アウトラインと注意アウトラインは、状態ごとにまとめて polyline として描画してよい。

推奨描画順序:

1. danger outline
2. caution outline
3. base route line
4. route markers / arrows / current location

ただし、danger と caution が重なる場合は danger が優先されること。

## 候補ルート切替時の仕様

候補ルートを切り替えた場合、表示中の候補ルートに合わせてアウトラインも切り替える。

- 選択中ルート: アウトライン表示あり
- 非選択ルート: 原則アウトライン非表示

ただし、現在の UI が複数候補を同時表示している場合は、選択中ルートのみ危険アウトラインを出す方針を優先する。
画面がうるさくなるため、全候補に危険アウトラインを常時出さないこと。

## OFF条件

以下の場合はアウトラインを表示しない。

- route geometry がない
- risk 判定情報がない
- 危険区間がない
- route risk scoring API が失敗した
- 既存ルート描画自体が失敗している

この場合も通常ルート表示は壊さないこと。

## UI文言の追加

余力があれば、情報パネルに短い凡例を追加する。

```text
線の外枠: 黄=この先/通過直後に注意、赤=危険区間
```

ただし画面を圧迫する場合は、凡例タブまたは既存の凡例表示に追加する。

## ログ

デバッグしやすいように、開発中のみ以下を確認できるようにする。

```js
console.debug('[route-risk-outline]', {
  routeIndex,
  segmentCount,
  dangerSegmentCount,
  cautionSegmentCount,
});
```

本番で過剰にログを出さないこと。

## 実装上の注意

- 既存の安全度スコア計算を壊さない
- 既存のルート候補 UI を壊さない
- 既存のハザード表示 ON/OFF と独立して動くようにする
- ハザードレイヤーが非表示でも、ルート危険アウトラインは route risk scoring の結果に基づいて表示してよい
- 低地・排水困難エリア単独は過剰に赤くしすぎないこと
- flood など明確な浸水想定と重なる区間は赤を優先する
- 低地のみの場合は黄色扱いにするか、既存 risk scoring の重みに合わせて調整する

## 受け入れ条件

- 候補ルート色が維持されている
- 危険区間が赤アウトラインで表示される
- 危険区間の手前が黄色アウトラインで表示される
- 危険区間の直後が黄色アウトラインで表示される
- 危険区間がないルートでは通常表示のままになる
- 候補ルート切替時にアウトラインも正しく切り替わる
- route risk scoring API 失敗時も通常ルート表示は壊れない
- スマホ表示で線が太すぎて地図が読めなくならない
- 既存の現在地マーカー、目的地マーカー、避難所アイコンを隠さない
- JS コンソールに致命的エラーが出ない
